# Санал, санаачилгын цахим платформ

ШУТИС-ийн оюутан, багш, ажилтны **санал, гомдлыг хариуцах нэгжид шууд хүргэж**,
**нийтийн санаачилгад дэмжлэг цуглуулах** веб систем.

Бакалаврын дипломын ажил · Д. Азжаргал (B210910806) · Программ хангамжийн инженерчлэл
Удирдагч: Г. Ганчимэг · Зөвлөх: Ж. Алимаа

## Системийн мөн чанар

Платформ хүсэлтийг шинж чанараар нь **хоёр сувагт** ялгана.

| | Хаалттай суваг | Нээлттэй суваг |
|---|---|---|
| Юу | Хувь хүнд хамаарах санал, гомдол | Олон нийтэд хамаарах санаачилга |
| Хэн харах | Гаргагч, хариуцсан нэгж, модератор | Бүх гишүүн |
| Дэмжлэг | Цуглуулахгүй | Босгод хүрэх хүртэл цуглуулна |
| Хугацаа | Гомдол 30, санал 90 **хуанлийн** хоног (хуулийн) | Цуглуулах 30 **хичээлийн** хоног |

Хаалттай гомдолд хугацаандаа хариу ирээгүй эсвэл хариу хангалтгүй бол **зөвхөн гаргагч
өөрөө** үүнийг нийтийн санаачилга болгон хөрвүүлж болно.

### Дэмжлэгийн босго

Босгыг тогтмол тоогоор бус, санаачилгын хамрах хүрээний гишүүдийн тооноос (N)
автоматаар тооцно:

```
B = ⌈ max( p·N , min( T_min , q·N ) ) ⌉        (Тайлангийн Томьёо 2.1)
```

анхдагчаар `p = 1%`, `T_min = 25`, `q = 20%`. Жишээ нь N = 15 194 → B = 152;
N = 23 → B = 5. Босго нь санаачилга **батлагдах үед нэг удаа** тооцогдож хөлддөг
тул цуглуулж байх хугацаанд өөрчлөгдөхгүй. Модератор босгын тоонд шууд нөлөөлөх
боломжгүй.

### Хоёр төрлийн цаг

* **Хуулийн хугацаа** — гомдол 30 хоног (нэг удаа ≤30 хоногоор сунгана), санал
  90 хоног. Хуанлийн өдрөөр тоологдож, хичээлийн амралтаар **зогсохгүй**.
* **Дотоод журмын хугацаа** — дэмжлэг цуглуулах, босго давсны дараах хариу.
  Хичээлийн өдрөөр тоологдож, амралтын үеүдийг **алгасна**. Хариу өгөх хугацааны
  хуанлийн нийт хоног 90-ээс хэтрэхгүй.

## Технологи

| Давхарга | Технологи |
|---|---|
| Frontend / Backend | Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4 |
| Өгөгдлийн сан | PostgreSQL 16 |
| ORM | Prisma 7 (`@prisma/adapter-pg` driver adapter) |
| Нэвтрэлт | ШУТИС SSO — OpenID Connect «authorization code» урсгал |
| Тест | Vitest (нэгж + интеграци) |

> **Тайлангийн Бүлэг 3.1-ээс ялгаатай нь:** backend-ийг тусдаа NestJS үйлчилгээ
> болгон салгалгүй, Next.js-ийн Server Actions болон Route Handlers дээр
> хэрэгжүүлэв. Модулийн хуваарилалт (Auth, Хүсэлт, Санаачилга, Модерац,
> Хугацаа/Босго, Мэдэгдэл, Цаг хэмжигч) тайлангийн зохиомжтой яг адил бөгөөд
> `src/lib/domain/`-д тусгаарлагдсан.

## Ажиллуулах

### 1. Өгөгдлийн сан

```bash
docker run -d --name sanal-db -p 5432:5432 \
  -e POSTGRES_PASSWORD=<нууц үг> -e POSTGRES_DB=sanaachilga \
  postgres:16-alpine
```

### 2. Орчны хувьсагч

`.env.local` файл үүсгэнэ (git-д орохгүй):

```
DATABASE_URL="postgresql://postgres:<нууц үг>@localhost:5432/sanaachilga?schema=public"
SSO_MOCK_SECRET="<санамсаргүй урт тэмдэгт мөр>"
CRON_SECRET="<санамсаргүй урт тэмдэгт мөр>"
```

### 3. Суулгах, бэлтгэх

```bash
npm install
npx prisma migrate deploy      # схемийг үүсгэнэ
npx prisma generate            # client үүсгэнэ
npm run seed                   # жишээ өгөгдөл
npm run dev
```

`npm run seed` нь тайлангийн Хүснэгт 2.26-гийн **яг жинхэнэ** тоонуудаар
(14 368 оюутан, 826 багш) өгөгдөл үүсгэдэг тул системийн тооцсон босго
тайлантай шууд тулгагдана.

### 4. Нэвтрэх

Хөгжүүлэлтийн орчинд жинхэнэ `auth.must.edu.mn`-д хандах боломжгүй тул
**ижил гэрээтэй хуурамч SSO** ажиллана (`src/lib/auth/mock-sso.ts`).
`/auth/login` → нэвтрэх дэлгэц дээр туршилтын кодуудыг жагсаасан байна:

| Код | Хэрэглэгч | Эрх |
|---|---|---|
| `B210910806` | Д. Азжаргал | Гишүүн (оюутан) |
| `DEMO-STUDENT` | Б. Сувдаа | Гишүүн (оюутан) |
| `DEMO-TEACHER` | Г. Ганчимэг | Гишүүн (багш) |
| `DEMO-MODERATOR` | Ж. Алимаа | Модератор |
| `DEMO-UNIT-SURGALT` | С. Болормаа | Нэгжийн хариуцагч |
| `DEMO-UNIT-OYUTAN` | Б. Энхтөр | Нэгжийн хариуцагч |
| `DEMO-ADMIN` | Т. Мөнхжаргал | Админ |

Жинхэнэ OIDC нийлүүлэгч нэмэхэд `SsoProvider` интерфейсийн шинэ хэрэгжүүлэлт
бичээд `currentProvider()`-ийг солихоос өөр өөрчлөлт шаардагдахгүй.

### 5. Цаг хэмжигч (FR-27)

Өдөр бүр 01:00 цагт дараах хаягийг дуудна:

```bash
curl -fsS -H "Authorization: Bearer $CRON_SECRET" http://localhost:3000/api/cron/daily
```

Админ самбараас гараар ч ажиллуулж болно.

### Бодлогын утгууд кодод БАЙХГҮЙ

NFR-13-ын дагуу босго (`p`, `T_min`, `q`), хугацаа, ангилал→нэгж холбоос,
хичээлийн амралтын хуанли бүгд өгөгдлийн санд хадгалагдаж, **админ самбараас**
тохируулагдана. `src/lib/rules/` дэх тогтмолууд нь зөвхөн **анхдагч** утга.
Өөрчлөлт бүр `audit_log`-д бичигдэнэ.

## Vercel дээр байршуулах

Багш, хянагчаар туршуулахад зориулсан байршуулалт. Төсөл нь PostgreSQL
шаарддаг тул өгөгдлийн санг эхлээд үүсгэнэ.

### 1. Өгөгдлийн сан үүсгэх

Vercel-ийн самбар → **Storage** → **Create Database** → **Neon** (Postgres).

Сонгох зүйлс:

| Талбар | Утга | Шалтгаан |
|---|---|---|
| Region | **Singapore** (`sin1`) | Монголд хамгийн ойр. `vercel.ts` дахь функцийн бүстэй ЗААВАЛ таарна |
| Auth | **Унтраах** | Манайх өөрийн нэвтрэлттэй, хэрэггүй |
| Realtime | Унтраалттай | Хэрэггүй |
| Plan | **Free** | 1 GB, манайд хангалттай |

> Сангийн бүс болон `vercel.ts` дахь `regions: ["sin1"]` нь **ижил** байх
> ёстой. Хуудас бүр өгөгдлийн сан руу хэд хэдэн дараалсан хүсэлт явуулдаг тул
> функц, сан хоёр өөр тив дээр байвал хуудас хэд дахин удаашрана.

Үүсгэсний дараа Neon integration төсөлд холболтын хувьсагчдыг **өөрөө** нэмнэ:

| Хувьсагч | Тайлбар |
|---|---|
| `DATABASE_URL` | **Pooled** — програм ажиллах үед ашиглана |
| `DATABASE_URL_UNPOOLED` | **Direct** — нүүлгэлтэд ашиглана (`prisma.config.ts` өөрөө таниж авна) |

### 2. Төслийг импортлох

[vercel.com/new](https://vercel.com/new) → `Rutone/diploma` репог импортлоно.

> **Анхаарах:** Production branch-ийг заавал **`ftest`** болгоно.
> Анхдагчаар `master` сонгогддог ч тэнд хуучин SQLite хувилбар байгаа тул
> байршуулалт амжилтгүй болно.
> Settings → Git → Production Branch → `ftest`.

Өгөгдлийн санг төсөлтэй холбоогүй бол: Storage → тухайн сан → **Connect Project**.

### 3. Орчны хувьсагч

Settings → Environment Variables дээр **гараар нэмэх** хоёр:

| Нэр | Утга |
|---|---|
| `SSO_MOCK_SECRET` | Санамсаргүй урт тэмдэгт мөр |
| `CRON_SECRET` | Санамсаргүй урт тэмдэгт мөр |

`DATABASE_URL`, `DATABASE_URL_UNPOOLED` хоёр аль хэдийн байгаа эсэхийг шалгана.

Санамсаргүй нууц үүсгэх:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 4. Байршуулалт

`ftest` салбарт push хийх бүрт Vercel автоматаар байршуулна. Build нь
`vercel-build` скриптийг ажиллуулж, **нүүлгэлтийг өөрөө хийнэ** —
гараар схем үүсгэх шаардлагагүй.

### 5. Жишээ өгөгдөл оруулах

Нэг удаа, өөрийн компьютерээс production сан руу:

```bash
DATABASE_URL="<DATABASE_URL_UNPOOLED-ийн утга>" npm run seed
```

Утгыг Vercel → Storage → тухайн сан → `.env.local` табаас авна.

> **Анхаар:** seed скрипт нь өгөгдлийн санг бүхэлд нь **цэвэрлэж** эхэлдэг.
> Build-ийн явцад хэзээ ч ажиллуулахгүй.

### 6. Цаг хэмжигч

`vercel.ts`-д өдөр бүр 17:00 UTC (= УБ-ийн 01:00) цагт `/api/cron/daily`
дуудахаар тохируулсан. `CRON_SECRET` тохируулсан үед Vercel уг нууцыг
`Authorization` толгойгоор дагуулж илгээнэ.

### Туршуулахаасаа өмнө

Систем туршилтын шатанд байгаа тул **нууц үг шалгахгүй** — холбоос мэдсэн
хэн ч дурын эрхээр, тэр дундаа админаар нэвтэрч чадна. Багш нарт үзүүлэхэд
асуудалгүй ч нийтэд ил тараахгүй байхыг анхаарна уу. Хаалттай байлгах бол
Vercel-ийн **Deployment Protection** тохиргоог ашиглаж болно.
